# 멋쟁이 타자처럼 인수인계

## 1. 작업 전 필수 확인

- 개발을 시작하기 전에 반드시 `PRD.md`와 `DESIGN.md`를 먼저 읽는다.
- `PRD.md`에는 제품 목표, 운영 정책, 게임 규칙과 기능 요구사항이 정리되어 있다.
- UI는 `DESIGN.md`의 색상, 타이포그래피, 간격, 컴포넌트 규칙을 기준으로 제작한다.
- 디자인 방향은 **경성시대 분위기가 아니라 빈티지하고 레트로한 방송국 분위기**다.
- 기존 `home.jsx`와 `channel-select.jsx`를 새 화면의 UI 참고 자료로 사용한다. 기존 화면의 정보 구조, 여백, 버튼, 카드, 채널별 포인트 컬러와 에셋 사용 방식을 최대한 이어간다.

## 2. 다른 컴퓨터에서 실행하기

다른 컴퓨터에서는 의존성이 설치되어 있지 않으므로 프로젝트 폴더에서 먼저 아래 명령을 실행한다.

```bash
npm install
npm run dev
```

- `react-router-dom`은 `package.json`에 의존성으로 등록되어 있으므로 `npm install` 실행 시 함께 설치된다.
- 만약 `react-router-dom`만 누락되어 있다면 `npm install react-router-dom`으로 설치한다.
- 화면은 노트북 `1920×1080` 해상도와 브라우저 `F11` 전체화면을 기준으로 제작되어 있다.
- localhost에서 확인할 때 반드시 `F11`을 켠 상태로 확인한다. 일반 브라우저 창에서는 화면이 잘려 보일 수 있다.

## 3. 현재 주요 파일

- `src/home.jsx`: 메인 홈 화면
- `src/channel-select.jsx`: 채널 선택 화면
- `src/main.jsx`: React Router 라우팅 설정
- `src/App.css`: 메인 홈 스타일
- `src/channel-select.css`: 채널 선택 화면 스타일
- `src/assets/images`: LP, 카세트, 타자기, ON AIR 등 이미지 에셋

## 4. 홈 화면에서 수정할 사항

- `home.jsx`의 카세트테이프 3개에서 채널 제목이 잘 보이지 않는 문제가 있다.
- 제목에 적용된 한 줄 제한과 말줄임표를 사용하지 말고, 필요한 경우 자연스럽게 줄바꿈하여 제목 전체가 보이도록 한다.
- 줄바꿈된 제목이 카세트 이미지의 주요 요소와 겹치지 않도록 위치와 여백을 세부 조정한다.
- `멋쟁이 타자처럼`이라는 메인 서비스 제목에만 봄바람체를 사용한다.
- 메인 서비스 제목을 제외한 제목, 본문, 버튼, 입력창 등 모든 UI 텍스트에는 Maru Buri를 사용한다.

## 5. 홈의 게임 시작 버튼

- 현재 `home.jsx`의 `게임 시작` 버튼은 `/select`로 이동하도록 연결되어 있다.
- 이 연결은 제거해야 한다.
- 게임 시작 버튼을 누른 다음 표시할 화면은 채널 선택 화면이 아니라 **참가자 확인 화면**이다.
- 참가자 확인 화면이 구현되면 게임 시작 버튼을 해당 화면으로 연결한다.
- 라우팅은 이미 설치 및 설정된 `react-router-dom`을 이어서 사용한다.

## 6. 게임 화면 핵심 디자인

- 게임이 실행되면 화면 하단 중앙에 타자기가 보여야 한다.
- 사용자가 물리 키보드의 키를 누르면 타자기 이미지의 대응하는 키가 하이라이트되어야 한다.
- 한글 입력에서도 조합된 글자가 아니라 `KeyboardEvent.code`를 기준으로 실제 누른 키 위치를 표시한다.
- 하이라이트는 `#EFF7FD`를 사용하며 키의 글자를 가리지 않도록 테두리 링, 옅은 내부 빛, 은은한 외부 글로우로 표현한다.
- 키를 누르는 즉시 하이라이트하고, 키를 뗀 뒤 약 100ms 안에 자연스럽게 사라지게 한다.
- 키 자체가 움직이거나 눌리고 흔들리는 애니메이션은 사용하지 않는다.
- 사용자가 화면 속 종이에 직접 타자를 치는 것처럼 보이도록 제시 문장과 입력 글자를 타자기 종이 위에 배치한다.

## 7. 문장 완료와 종이 이동

- 문장 하나를 완성할 때마다 타자기의 종이가 위로 이동한다.
- 다음 문장은 종이의 새로운 빈 줄에 출력한다.
- 종이 이동 애니메이션이 진행되는 동안에도 다음 문장의 키 입력을 계속 받을 수 있어야 한다.
- 이미 입력을 완료한 문장은 종이 위에 남겨 둔다.
- 화면 크기가 제한되어 있으므로 한 번에 최근 두 문장까지만 보이도록 구성한다.
- 세 번째 문장이 등장하면 첫 번째 문장이 종이 위쪽으로 이동하며 사라지고, 두 번째 문장과 세 번째 문장이 남는 방식으로 처리한다.
- 이후에도 같은 방식으로 가장 오래된 문장을 위로 밀어내며 최근 두 문장을 유지한다.

## 8. 로딩 화면

- 로딩 화면은 화면 정중앙에 크지 않은 LP판 하나가 회전하는 형태로 제작한다.
- 전체 디자인은 `DESIGN.md`의 색상과 빈티지·레트로 분위기를 유지한다.

## 9. ON AIR 상태

- ON AIR 에셋은 화면 위쪽 중앙에 배치하고 원본 비율을 유지한다.
- 홈, 참가자 확인, 게임 안내, 결과 화면에서는 꺼진 ON AIR 에셋을 표시한다.
- 카운트다운이 끝나고 게임이 실제로 시작되는 순간 켜진 ON AIR 에셋으로 변경한다.
- 게임이 진행되는 동안 켜진 상태를 유지한다.
- 마지막 문장을 완료하거나 게임이 종료되면 꺼진 ON AIR 에셋으로 교체해 방송이 끝난 느낌을 살린다.
- 켜진 에셋: `src/assets/images/ON AIr_light on .png`
- 꺼진 에셋: `src/assets/images/ON Air_light off .png`
- 현재 파일명에는 공백과 대소문자 차이가 있으므로 import 경로를 정확히 작성한다.

## 10. 디자인 재사용 기준

- `home.jsx`와 `channel-select.jsx`의 상단 마스트헤드 구성과 정보 밀도를 참고한다.
- 화면 좌우 여백은 `64px`을 기본으로 유지한다.
- 버튼 크기, 모서리, 카드 테두리와 채널별 포인트 컬러는 `DESIGN.md`의 값을 그대로 사용한다.
- 채널별 LP와 아이콘은 `DESIGN.md`에 정의된 매핑을 그대로 사용한다.
- 빈티지하고 레트로한 분위기는 유지하되 얼룩, 먼지, 찢김 등 지저분한 낡은 질감은 사용하지 않는다.
- 그라데이션과 그림자는 완전 금지 사항은 아니지만 가급적 사용하지 않는다. 꼭 필요한 경우에도 디자인 분위기를 보조하는 최소한의 범위로 제한한다.
- 과도한 둥근 모서리, 글래스모피즘, 과한 네온과 3D 효과는 사용하지 않는다.

## 11. 인수인계 시 우선 작업 순서

1. `PRD.md`와 `DESIGN.md` 확인
2. 다른 컴퓨터라면 `npm install` 실행
3. 홈 게임 시작 버튼의 `/select` 연결 제거 및 참가자 확인 화면 연결 준비
4. 홈 카세트테이프 3개의 제목 가독성 수정
5. 로딩 화면 제작
6. 참가자 확인 이후 필요한 화면 제작
7. 타자기 키 하이라이트, 종이 이동, ON AIR 상태 전환 구현
8. `1920×1080` 및 `F11` 전체화면에서 최종 확인
